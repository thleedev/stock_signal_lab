# 시나리오 06 — 사용자 포트폴리오 관리

> 사용자가 모의 매수를 기록하고 수익률을 추적하는 흐름입니다.
> 관련 문서: 04(API §2.4), 08(프론트엔드 §4.5)

## 개념 구분

이 시스템에는 성격이 다른 포트폴리오 3종이 공존합니다.

| 종류 | 테이블 | 조작 주체 |
|------|--------|-----------|
| 가상매매 (AI) | `virtual_trades` | 신호가 자동 기록 (시나리오 05) |
| 사용자 포트폴리오 | `user_portfolios`·`user_trades` | 사용자가 `/my-portfolio`에서 수동 기록 |
| 알파캐치 보유 | `alphacatch_holdings` | 수집기가 화면 스크래핑으로 덮어쓰기 |

구세대 `/investment` 화면은 별도 `watchlist` 테이블(매수가·손절가·목표가)을 씁니다.

## 기본 흐름 — 매수 기록

1. `/my-portfolio`에서 종목을 검색해 선택하면 매수 모달이 열립니다.
2. `POST /api/v1/user-portfolio/trades`가 BUY 행을 만듭니다. 목표가·손절가는 BUY에만 저장합니다.
3. 보유 목록은 SELL이 참조하지 않는 BUY(미청산 포지션)로 계산합니다.
4. 현재가는 `stock_cache`를 우선하고 없으면 일봉 종가로 폴백합니다. 5분 주기 폴링이 장중 가격을 갱신합니다.
5. 행에는 등급 배지(`stock_scores.score_total` 기준), 최신 신호, 목표·손절 근접 상태(`near_target`은 목표가의 97% 이상, `near_stop`은 손절가의 103% 이하)가 표시됩니다.

## 청산 흐름

1. 보유 행의 제거 버튼은 두 선택지를 줍니다.
   - 거래 완료: 현재가에서 세금·수수료 0.25%를 차감한 매도가로 SELL 행을 만들고 `buy_trade_id`로 연결합니다.
   - 단순 삭제: 매도 기록 없는 BUY만 DELETE할 수 있습니다.
2. 이미 매도된 매수를 다시 매도하려 하면 409를 반환합니다.

## 관리 기능

- 포트 탭에서 다중 포트를 만들고, 행 드래그로 종목을 다른 포트로 옮깁니다(PATCH로 `portfolio_id` 변경).
- 손절가·목표가는 연필 아이콘으로 인라인 편집하며 퍼센트 프리셋(목표 +5~+20%, 손절 -3~-10%)을 제공합니다.
- 포트 삭제는 소프트 삭제(`deleted_at`)이며 같은 이름으로 다시 만들면 복원됩니다. 기본 포트는 삭제할 수 없습니다.
- AI 매도신호가 있는 보유 종목에는 경고 아이콘이 붙고, 손절·목표 도달 행은 배경색으로 강조됩니다.

## 성과 추적

- `GET /api/v1/user-portfolio/performance`가 `user_portfolio_snapshots`와 KOSPI 벤치마크(일봉의 KOSPI 행)를 반환하고, 성과 비교 팝업이 recharts로 그립니다.
- 스냅샷을 쌓는 `cron/user-portfolio-snapshot`은 호출자가 없는 미연결 상태입니다. GHA 전환 때 연결이 유실되어 스냅샷이 자동 적재되지 않으므로, 성과 차트를 쓰려면 크론 연결 복구가 필요합니다.

## 종목 상세 패널 연동

어느 화면이든 종목을 클릭하면 열리는 상세 패널에서 포트 매수 기록·차트 오버레이(매수·목표·손절 프라이스 라인)를 함께 볼 수 있습니다. `/stock/[symbol]` 전용 페이지도 포트 체크박스로 같은 오버레이를 지원합니다.
